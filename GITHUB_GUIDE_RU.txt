SECNOTE 1.3 — ПОЛНАЯ ИНСТРУКЦИЯ ДЛЯ GITHUB

ЭТА ИНСТРУКЦИЯ ПОДХОДИТ ДЛЯ ДВУХ СЛУЧАЕВ:
A. Обновление существующего репозитория SecNote 1.2.
B. Создание репозитория с нуля.

============================================================
A. ОБНОВЛЕНИЕ СУЩЕСТВУЮЩЕГО РЕПОЗИТОРИЯ SECNOTE 1.2
============================================================

1. СКАЧАЙТЕ И РАСПАКУЙТЕ АРХИВ
- Используйте SecNote-v1.3-Repo-Root.zip.
- Распакуйте архив на компьютере.
- Внутри лежат файлы проекта непосредственно от корня репозитория: app/, signing/, .github/, settings.gradle.kts и т.д.

2. ОТКРОЙТЕ СВОЙ РЕПОЗИТОРИЙ
- Откройте GitHub и перейдите именно в тот репозиторий, из которого собирали SecNote 1.2.
- Рекомендуемая видимость репозитория — Private.
- Не создавайте новый репозиторий, если хотите обновить установленный SecNote поверх старой версии.

3. ЗАГРУЗИТЕ ФАЙЛЫ ПРОЕКТА
- Нажмите Add file -> Upload files.
- Откройте распакованную папку SecNote-v1.3-Repo-Root.
- Перетащите в форму GitHub всё её содержимое: app/, signing/, build.gradle.kts, settings.gradle.kts, gradle.properties, README_RU.md, GITHUB_GUIDE_RU.txt и .gitignore.
- Не загружайте ZIP-файл как один файл.
- Подтвердите замену совпадающих файлов (особенно app/src/main/java/infernics/notes/MainActivity.kt, NoteRepository.kt, app/build.gradle.kts и FileVaultRepository.kt).
- Сохраните signing/secure-notes-debug.keystore. В архиве 1.3 он совпадает с ключом из архива SecNote 1.2. Если в вашем репозитории уже есть этот файл, не удаляйте его и не заменяйте неизвестным ключом.

4. ОБНОВИТЕ WORKFLOW — ЭТО ОБЯЗАТЕЛЬНО
Workflow версии 1.2 может проверять versionName 1.2 и versionCode 3. Если оставить старый YAML, сборка 1.3 может завершиться ошибкой проверки версии.

Надёжный способ через веб-интерфейс GitHub:
- Откройте в репозитории .github/workflows/build-apk.yml.
- Нажмите карандаш Edit.
- Полностью замените содержимое на текст из отдельного файла SecNote-v1.3-build-apk.yml.
- Нажмите Commit changes.

Если файла ещё нет:
- Add file -> Create new file.
- Имя: .github/workflows/build-apk.yml
- Вставьте содержимое SecNote-v1.3-build-apk.yml.
- Commit changes в основную ветку main.

ВАЖНО ПРО СКРЫТУЮ ПАПКУ:
GitHub Upload files иногда не показывает .github при перетаскивании папки. Не пытайтесь загружать её много раз. Создайте или отредактируйте файл вручную, как описано выше. В репозитории должен существовать ровно один нужный workflow.

5. ЗАПУСТИТЕ СБОРКУ
- Откройте Actions.
- Выберите Build SecNote APK.
- Если автоматический запуск не начался, нажмите Run workflow и выберите ветку main.
- Откройте самый последний запуск.
- Дождитесь зелёной галочки у job Test and build SecNote 1.3.2.
- При красном крестике откройте job, затем шаг Run unit tests and build APK. Для диагностики нужны первая строка с 'e:' или блок 'What went wrong' и следующие строки.

6. СКАЧАЙТЕ APK
- В успешном запуске найдите Artifacts.
- Скачайте artifact app-debug.apk. Workflow загружает один APK отдельным файлом (без дополнительного ZIP-архива).
- Если браузер всё же сохраняет его как архив или меняет имя, не переименовывайте APK вручную из другого файла; используйте оригинальный артефакт.

7. УСТАНОВИТЕ ОБНОВЛЕНИЕ
- Установите APK поверх SecNote 1.2.
- Не удаляйте старое приложение перед установкой: удаление приложения стирает его локальное приватное хранилище.
- При совпадении Package ID и подписи Android должен предложить обновить приложение.
- Параметры версии: Package ID infernics.notes, versionName 1.3, versionCode 4.

============================================================
B. ЕСЛИ РЕПОЗИТОРИЙ НОВЫЙ
============================================================

1. Создайте репозиторий на https://github.com/new.
2. Выберите Private.
3. Не добавляйте шаблон README, .gitignore или License, чтобы избежать конфликта первого коммита (можно создать пустой репозиторий).
4. Распакуйте SecNote-v1.3-Repo-Root.zip.
5. Add file -> Upload files.
6. Перетащите всё содержимое распакованной папки в корень репозитория, включая app/ и signing/.
7. Commit changes в ветку main.
8. Если .github не появилась, вручную создайте .github/workflows/build-apk.yml и вставьте содержимое из SecNote-v1.3-build-apk.yml.
9. После Commit откройте Actions. Workflow Build SecNote APK должен запуститься.
10. Скачайте app-debug.apk из Artifacts после успешного выполнения.

============================================================
ЧТО НОВОГО В SECNOTE 1.3
============================================================

- В настройках есть переключатель блокировки скриншотов (Android FLAG_SECURE).
- В файловом хранилище можно включить массовый выбор кнопкой в верхней панели либо долгим нажатием по элементу.
- Выбранные фото и файлы можно массово расшифровать в выбранную папку или удалить из хранилища.
- В главной панели вместо подписи «Настройки» оставлена только шестерёнка стандартного размера.
- В типе «Список» новая строка прямо внутри редактора получает свой чекбокс. После ввода пункта нажмите Enter/Next — появится следующая строка с чекбоксом и курсор перейдёт в неё. Обычная заметка остаётся свободным текстом.
- Галерея фотографий и список документов сохранены.
- Биометрия и автоблокировка сохранены.

============================================================
ВАЖНЫЕ ПРЕДУПРЕЖДЕНИЯ
============================================================

- Не удаляйте приложение перед установкой обновления: можно потерять данные.
- Не заменяйте keystore другим ключом при обновлении.
- Репозиторий должен быть Private, поскольку в нём хранится debug-keystore для подписи личных APK.
- Если keystore ранее публиковался в открытом репозитории, считайте его раскрытым для подписи. Не используйте его для публичного/магазинного релиза.
- Debug APK не предназначен для Google Play.
- Блокировка скриншотов защищает окно приложения системным флагом Android, но не может помешать фотографированию экрана внешней камерой.
- При массовой расшифровке выбранные файлы попадают в папку, которую выбирает пользователь. Экспортированные файлы находятся вне защищённого хранилища SecNote.
- При импорте приложение может пытаться удалить оригинал после сохранения зашифрованной копии, но Android-провайдер или flash-память не гарантируют физическое стирание старых блоков.

ЕСЛИ СБОРКА НЕ УДАЛАСЬ:
Откройте Actions -> последний красный запуск -> job Test and build SecNote 1.3.2 -> шаг Run unit tests and build APK. Пришлите лог начиная с первой ошибки 'e:' или раздела 'What went wrong'.
