# SecNote — отчёт по этапу 2D: защита ключевого материала и биометрического входа

## База

Этап выполнен поверх архива `SecNote-v1.4.14-phase2C-legacy-stream-migration.zip`. Изменения этапов 1, 2A, 2B и 2C сохранены.

## Что изменено

### 1. Обёртка соли основного хранилища (SCK2)

- Новый формат `SCK2` использует AES-256-GCM Android Keystore с дополнительными аутентифицируемыми данными (AAD), фиксирующими назначение шифротекста: `SecNote/Keystore/salt/v2`.
- Старый формат `SCK1` продолжает распознаваться и расшифровываться без AAD — это необходимо для совместимости с уже установленными версиями.
- При успешной проверке действующего ключа `ensureSaltWrapped` автоматически перезаписывает старую обёртку в `SCK2`.
- Перезапись выполняется только после проверки файла `key.check`; если проверка не проходит, исходный ключевой материал не заменяется.
- Соль по-прежнему случайная, 16 байт; содержимое заметок и файлов не перешифровывается.

### 2. Биометрический вход

- Сохранение обёрнутого ключа теперь синхронное (`commit`), а не отложенное (`apply`): интерфейс не сообщает об успешном включении до завершения сохранения.
- Проверяется ожидаемая длина зашифрованного 256-битного ключа (48 байт вместе с GCM-тегом) и IV (12 байт).
- Ограничена длина строк Base64 до декодирования; некорректные или неожиданные данные сбрасывают только биометрическую настройку, не основное хранилище.
- Временные массивы обёрнутого ключа и IV очищаются после использования, отмены или ошибки.
- Основной пароль остаётся доступным резервным способом входа; биометрия остаётся добровольной.

### 3. Проверка длинных и Unicode-паролей

- Добавлен регрессионный тест: длинная парольная фраза с кириллицей и emoji участвует в получении ключа полностью; изменение последнего символа приводит к другому ключу.
- Ограничения длины пароля не вводились, обрезание пароля не добавлялось.

## Что намеренно не менялось

- Алгоритм получения ключа основного хранилища остаётся PBKDF2-HMAC-SHA256, 250 000 итераций, 256 бит.
- PBKDF2-параметры panic-пароля и скрытого хранилища не менялись.
- Не менялись форматы зашифрованных заметок, файлов и резервных копий, кроме уже внесённых на предыдущих этапах изменений.
- Не менялись правила автоблокировки; принудительная блокировка при переключении приложений не добавлялась.

Увеличение параметров KDF или переход на Argon2id нельзя безопасно делать простым изменением числа итераций: это изменит производный ключ и лишит приложение доступа к существующим данным. Для такого изменения нужна отдельная версия формата ключевого состояния, проверенная процедура перехода и тесты восстановления из старых резервных копий. Поэтому KDF оставлен без изменений в этом этапе.

## Проверки

- `Crypto.kt` скомпилирован отдельно с `kotlinc`.
- Smoke-тест прошёл: длинная Unicode-парольная фраза, AES-GCM round-trip и contextual AAD.
- Проверены баланс скобок и целостность изменённых исходных файлов.
- Полную Android-сборку, тесты с Android Keystore и биометрией локально выполнить не удалось: в рабочем окружении нет Android SDK/Gradle wrapper. Обязательная проверка — GitHub Actions после загрузки архива.
