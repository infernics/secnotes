# SecNote — отчёт по этапу 2B

## Цель

Привязать содержимое каждого нового файла в файловом хранилище к его логическому идентификатору. Это закрывает сценарий подмены, при котором корректно зашифрованный файл можно было перенести под идентификатор другого объекта в том же хранилище.

## Что изменено

1. Добавлен потоковый формат `SNF2` для файлов хранилища.
   - Каждый блок AES-GCM аутентифицирует домен и ID файла вместе с индексом и длиной блока.
   - Зашифрованный завершающий блок также аутентифицирует домен и ID, число блоков и общий размер.
   - Сохранена обработка потоками с ограниченным буфером; весь файл не загружается в память.
2. Новые импорты файлов и фотографии записываются в `SNF2` с контекстом `file-data` + ID.
3. Все операции чтения и проверки файлового хранилища передают ожидаемый ID: экспорт, миниатюры, проверка после импорта, определение даты фотографии и проверка резервной копии.
4. `SNF1` оставлен для совместимости со старыми файлами и внешним контейнером резервной копии. Контекстный API умеет читать старые `SNF1`, но не считает их привязанными к ID.
5. Формат внешнего зашифрованного архива резервной копии не изменён: он по-прежнему использует общий `SNF1`-поток и собственный пароль.
6. Добавлены тесты на привязку потока к ID/домену, обязательность контекста для `SNF2` и чтение старого `SNF1` через новый API.

## Совместимость и ограничения

- Существующие файлы `SNF1` не теряют доступность: приложение продолжает их читать.
- На этом подэтапе старые `SNF1`-файлы автоматически не перешифровываются. Они сохраняют прежнее свойство отсутствия привязки к ID до отдельной безопасной миграции. Новые импорты уже используют `SNF2`.
- Для автоматической миграции старых больших файлов требуется отдельная процедура с временным файлом, проверкой целостности и безопасной заменой; её нельзя смешивать с обычным чтением без отдельной проверки отказоустойчивости.
- Параметры KDF/паролей, авто-блокировка и UX не менялись.

## Проверки, выполненные здесь

- `Crypto.kt` успешно скомпилирован отдельно через `kotlinc`.
- Запущен smoke-тест: `SNF2` round-trip, отказ при другом ID, отказ при отсутствии контекста, чтение старого `SNF1` через контекстный API и сохранение общего потокового API. Результат: OK.
- Проверены все вызовы потокового шифрования/дешифрования в исходниках: файловое хранилище использует контекстный API; контейнер резервной копии — прежний общий API.
- Android Gradle build и полный JUnit-набор в этой среде не запускались. Окончательная проверка — GitHub Actions после загрузки архива.
