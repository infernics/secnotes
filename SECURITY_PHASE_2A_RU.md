# SecNote — отчёт по этапу 2A: привязка записей к контексту

## Объём изменений

Этот пакет продолжает исправления этапа 1. В нём изменены:

- `Crypto.kt` — добавлен версионированный формат `SNE2` для контекстно-аутентифицированных записей; добавлены функции шифрования/расшифрования с AAD и построение доменно-разделённого контекста.
- `NoteRepository.kt` — новые заметки шифруются с AAD, включающим пространство `note-record` и ID заметки. При чтении ID внутри JSON сверяется с именем файла. Старые записи читаются в legacy-режиме и после успешного чтения/проверки ID по возможности переписываются в новый формат.
- `FileVaultRepository.kt` — метаданные файлов шифруются с AAD, включающим `file-metadata` и ID файла. ID теперь также хранится внутри новых JSON-метаданных и сверяется при чтении. Старые метаданные принимаются для миграции и переписываются после успешного чтения.
- `BackupManager.kt` — проверка содержимого резервной копии обновлена для чтения как legacy-записей, так и новых записей `SNE2` с соответствующим AAD.
- `CryptoTest.kt` — добавлены тесты запрета переноса записи между разными ID и разными доменами, а также совместимости чтения legacy-формата.

## Почему это важно

AES-GCM уже обнаруживал изменение зашифрованных байтов, но без AAD не различал назначение объекта. Если два объекта были зашифрованы одним ключом, валидный шифротекст можно было целиком подменить другим валидным шифротекстом. Новый формат связывает аутентификацию с типом записи и её идентификатором.

## Совместимость и миграция

- Старый формат заметок и метаданных не удаляется и остаётся читаемым.
- Миграция выполняется постепенно при чтении объекта.
- Если переписывание legacy-записи не удалось, успешно прочитанное содержимое всё равно возвращается приложению, а исходный файл остаётся на месте; миграция повторится при следующем чтении.
- Новые записи используют маркер `SNE2`; повреждённая запись `SNE2` не должна незаметно откатываться к legacy-дешифрованию.
- Проверка резервной копии понимает оба формата.

## Что пока не входит в этот подэтап

- Потоковое шифрование содержимого файлов (`SNF1`) пока не получило привязку к ID файла. Это отдельная следующая часть 2B, где потребуется новый формат потока и совместимое чтение старых файлов.
- PBKDF2 пока не заменяется на Argon2id и число итераций не меняется: изменение KDF требует отдельного этапа с проверкой миграции ключей и производительности на реальных Android-устройствах.
- Формат резервного контейнера и debug-подпись не менялись.
- Release-сборка не выполнялась и не менялась.

## Проверки

В этой среде выполнена компиляция `Crypto.kt` локальным Kotlin-компилятором и smoke-проверка:

- новый контекстный шифротекст успешно расшифровывается с исходным AAD;
- тот же шифротекст отвергается с другим ID;
- legacy-шифротекст продолжает читаться для миграции.

Полная Android-сборка и JUnit-набор должны быть подтверждены GitHub Actions. До зелёного CI пакет не следует считать полностью проверенным.

## Важное замечание

Для новых записей подмена между объектами блокируется криптографически. Legacy-записи неизбежно читаются без AAD ради совместимости; их защита усиливается после миграции. Поэтому не следует считать старые данные полностью защищёнными от подмены до их первого успешного чтения и переписывания.
