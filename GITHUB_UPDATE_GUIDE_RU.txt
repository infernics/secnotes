SECNOTE 1.3.3 — ИНСТРУКЦИЯ ОБНОВЛЕНИЯ ЧЕРЕЗ GITHUB

Это точечное обновление к SecNote 1.3.2. Оно добавляет секретный пароль экстренного уничтожения и не включает другие запрошенные ранее изменения.

ПЕРЕД НАЧАЛОМ
- Используйте тот же GitHub-репозиторий, где хранится SecNote 1.3.2.
- Не создавайте новый репозиторий.
- Убедитесь, что репозиторий имеет статус Private.
- Не удаляйте и не заменяйте signing/secure-notes-debug.keystore.

ШАГ 1. СКАЧАЙТЕ И РАСПАКУЙТЕ АРХИВ
Распакуйте SecNote-1.3.3-Repo-Root.zip на компьютере. Внутри находятся файлы проекта, а также скрытая папка .github.

ШАГ 2. ОБНОВИТЕ ФАЙЛЫ В СУЩЕСТВУЮЩЕМ РЕПОЗИТОРИИ
1. Откройте страницу Code вашего текущего репозитория.
2. Нажмите Add file → Upload files.
3. Перетащите СОДЕРЖИМОЕ распакованной папки в корень репозитория (не сам ZIP и не папку-обёртку).
4. Когда GitHub предложит замену, подтвердите её.
5. Важно: файл signing/secure-notes-debug.keystore должен остаться прежним. Если загрузчик предлагает заменить его, пропустите этот файл.
6. Нажмите Commit changes и сохраните в ветку main.

ШАГ 3. ПРОВЕРЬТЕ WORKFLOW
Убедитесь, что в репозитории есть файл:
.github/workflows/build-apk.yml

В ZIP этот файл уже присутствует. Если скрытая папка .github не загрузилась через веб-интерфейс, создайте файл вручную:
Add file → Create new file
Имя: .github/workflows/build-apk.yml

Содержимое можно взять из файла SecNote-1.3.3-build-apk.yml, приложенного рядом с архивом. Вставьте его целиком и нажмите Commit changes.

ШАГ 4. ЗАПУСТИТЕ СБОРКУ
1. Откройте вкладку Actions.
2. Выберите Build SecNote APK.
3. Если запуск не начался автоматически, нажмите Run workflow для ветки main.
4. Откройте последний запуск и дождитесь зелёной галочки.
5. Внизу страницы откройте Artifacts и скачайте app-debug.apk.

ШАГ 5. УСТАНОВИТЕ ОБНОВЛЕНИЕ
1. Не удаляйте SecNote 1.3.2 с телефона.
2. Установите app-debug.apk поверх предыдущей версии.
3. После запуска откройте Настройки → Безопасность → Секретный пароль уничтожения.
4. Установите отдельный секретный пароль и повторите его. Не используйте основной пароль.
5. Не проверяйте самоуничтожение на единственной копии важных данных: это необратимая операция. Для проверки используйте тестовое хранилище и тестовые записи.

ЧТО ПРОИСХОДИТ ПРИ ВВОДЕ СЕКРЕТНОГО ПАРОЛЯ
Он вводится в обычное поле блокировки. SecNote записывает устойчивый маркер, показывает «Попытки исчерпаны», затем запускает очистку без дополнительного подтверждения. Если приложение или телефон перезапустятся во время процедуры, очистка возобновится при следующем старте до показа доступа к хранилищу.

ВАЖНО ОБ ОГРАНИЧЕНИЯХ
Обычное приложение Android не может гарантировать физическое уничтожение каждого старого блока flash-памяти. SecNote удаляет ключи и app-owned локальные данные; перезапись файлов является best-effort. Внешние/облачные/экспортированные копии за пределами приватных папок приложения этим не удаляются.
