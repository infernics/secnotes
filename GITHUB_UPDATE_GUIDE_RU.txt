SECNOTE 1.4.2 — ПОЛНАЯ ИНСТРУКЦИЯ ОБНОВЛЕНИЯ ЧЕРЕЗ GITHUB

Это обновление для существующей SecNote 1.4.1. Новый репозиторий создавать не нужно.

ПЕРЕД НАЧАЛОМ
- Откройте тот же GitHub-репозиторий, где хранится рабочая SecNote 1.4.1.
- Убедитесь, что репозиторий имеет статус Private.
- Package ID должен оставаться infernics.notes.
- Не удаляйте, не заменяйте и не переименовывайте signing/secure-notes-debug.keystore.
- Не удаляйте SecNote с телефона и не очищайте данные приложения.

ШАГ 1. СКАЧАЙТЕ И РАСПАКУЙТЕ АРХИВ
1. Скачайте SecNote-v1.4.2-Repo-Root.zip.
2. Распакуйте ZIP на компьютере.
3. Откройте распакованную папку. В её корне должны быть видны:
   .github/
   app/
   signing/
   settings.gradle.kts
   build.gradle.kts
   gradle.properties
   README_RU.md
   GITHUB_UPDATE_GUIDE_RU.txt

ШАГ 2. ОБНОВИТЕ ФАЙЛЫ В СУЩЕСТВУЮЩЕМ РЕПОЗИТОРИИ
1. Откройте текущий Private Repository с SecNote 1.4.1.
2. Перейдите на вкладку Code.
3. Нажмите Add file → Upload files.
4. Перетащите СОДЕРЖИМОЕ распакованной папки в корень репозитория. Не загружайте сам ZIP и не создавайте вложенную папку проекта.
5. Подтвердите замену совпадающих файлов.
6. ВАЖНО: сохраните прежний signing/secure-notes-debug.keystore. Если GitHub предлагает заменить его файлом из архива, пропустите keystore и оставьте существующий.
7. Нажмите Commit changes и сохраните изменения в ветку main.

ШАГ 3. ПРОВЕРЬТЕ GITHUB ACTIONS WORKFLOW
В репозитории должен существовать файл:
  .github/workflows/build-apk.yml

Если папка .github не видна или workflow не обновился:
1. Откройте существующий .github/workflows/build-apk.yml и нажмите Edit (карандаш).
2. Замените всё содержимое текстом из файла SecNote-v1.4.2-build-apk.yml.
3. Нажмите Commit changes.

Если workflow ещё отсутствует:
1. Нажмите Add file → Create new file.
2. В имя файла вставьте строго:
   .github/workflows/build-apk.yml
3. Вставьте всё содержимое SecNote-v1.4.2-build-apk.yml.
4. Нажмите Commit changes в ветку main.

ШАГ 4. ПРОВЕРЬТЕ ВЕРСИЮ ПРОЕКТА
Откройте app/build.gradle.kts. Должно быть:
  applicationId = "infernics.notes"
  namespace = "infernics.notes"
  versionCode = 10
  versionName = "1.4.2"

Также проверьте наличие прежнего файла:
  signing/secure-notes-debug.keystore

ШАГ 5. ЗАПУСТИТЕ ОБЛАЧНУЮ СБОРКУ
1. Откройте вкладку Actions.
2. Выберите Build SecNote APK.
3. После commit сборка должна стартовать автоматически. Если нет, нажмите Run workflow и выберите ветку main.
4. Проверьте шаг Verify project files and application identity — он должен завершиться успешно.
5. Дождитесь зелёной галочки у Run unit tests and build APK.
6. Откройте успешный запуск, внизу найдите Artifacts и скачайте app-debug.apk.

ШАГ 6. УСТАНОВИТЕ ОБНОВЛЕНИЕ
1. Не удаляйте SecNote 1.4.1 с телефона.
2. Установите новый app-debug.apk поверх предыдущей версии.
3. Если Android сообщает о конфликте подписи, остановитесь. Не удаляйте приложение с данными — проверьте, что в репозитории сохранился исходный keystore.
4. Откройте SecNote и проверьте в настройках версию 1.4.2.

ЧТО ИЗМЕНИЛОСЬ В 1.4.2
- Убран диалог «Переместить файл в зашифрованное хранилище?». После выбора файл импортируется сразу.
- Системный файловый менеджер теперь разрешает выбрать несколько файлов за один раз.
- Каждый файл шифруется и сохраняется отдельно. Ошибка с одним файлом не должна отменять импорт остальных.
- После импорта показывается число добавленных файлов, количество перезаписанных/удалённых оригиналов и список ошибок.
- Возврат из выбора файлов, отмена выбора и возврат из выбора папки для массовой расшифровки больше не должны принудительно выводить приложение на экран пароля.
- На время системного picker-экрана таймер автоблокировки приостанавливается; после возврата отсчёт начинается заново.

ШАГ 7. ПРОВЕРЬТЕ НА ТЕЛЕФОНЕ
Проверку лучше провести с неважными тестовыми файлами.

A. Один файл
1. Установите автоблокировку «Мгновенно» для максимально строгой проверки.
2. Откройте файловое хранилище и нажмите плюс.
3. Выберите один тестовый файл и подтвердите выбор.
4. Убедитесь, что дополнительного диалога нет, файл появляется в хранилище и SecNote остаётся открытым.
5. Проверьте сообщение о результате удаления оригинала. Android-провайдер может не разрешить запись или удаление — в таком случае SecNote сообщит об этом.

B. Несколько файлов
1. Повторите импорт, выбрав несколько фото и документов.
2. Убедитесь, что все поддержанные файлы появились в хранилище.
3. Проверьте итоговое сообщение: количество импортированных, удалённых оригиналов и неудачных элементов.

C. Отмена выбора
1. Нажмите плюс.
2. Закройте системный файловый менеджер кнопкой «Отмена» или системной кнопкой «Назад».
3. Убедитесь, что SecNote остаётся в файловом хранилище и не показывает экран пароля.

D. Настройка автоблокировки 1 минута
1. Установите автоблокировку на 1 минуту.
2. Откройте системный выбор файлов, выберите документ и вернитесь в SecNote быстрее минуты.
3. Убедитесь, что приложение не заблокировалось немедленно.
4. После возвращения сверните SecNote обычным способом и убедитесь, что дальнейшая автоблокировка срабатывает по настройке.

E. Экспорт и массовая расшифровка
1. Экспортируйте один тестовый файл.
2. Выделите несколько файлов, начните массовую расшифровку и выберите папку назначения.
3. Убедитесь, что возврат из выбора папки не блокирует приложение.

ВАЖНЫЕ ОГРАНИЧЕНИЯ
- SecNote сначала сохраняет зашифрованную копию и только после этого пытается перезаписать/удалить исходник.
- Сторонние и облачные файловые провайдеры могут запретить запись или удаление. Проверьте итоговый статус и при необходимости удалите оригинал вручную.
- Обычное Android-приложение не может гарантировать физическое уничтожение всех старых flash-блоков, облачных версий или резервных копий.

НЕ ДЕЛАЙТЕ
- Не меняйте applicationId и namespace.
- Не уменьшайте versionCode.
- Не удаляйте SecNote перед установкой обновления.
- Не удаляйте и не заменяйте keystore.
- Не делайте репозиторий публичным.
- Не публикуйте секретный пароль уничтожения.
