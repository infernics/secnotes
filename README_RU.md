# SecNote 1.3.3

Патч к рабочей версии SecNote 1.3.2. В этой версии добавлен **только секретный пароль экстренного уничтожения**; остальные экраны и функции 1.3.2 сохранены без изменений.

- **Название:** SecNote
- **Package ID:** `infernics.notes`
- **Version:** `1.3.3` (versionCode `7`)
- **Минимальный Android:** 8.0 (API 26)
- **Compile SDK:** 35
- **Java:** 17
- **Gradle:** 8.7

## Как включить

1. Откройте SecNote и перейдите в Настройки → Безопасность.
2. В строке «Секретный пароль уничтожения» нажмите «Установить».
3. Задайте отдельный пароль от 8 символов и повторите его. Он не должен совпадать с основным паролем.
4. После сохранения настройка будет отображаться как включённая.

## Сценарий экстренного уничтожения

Секретный пароль вводится **в то же поле**, где обычно вводится основной пароль. Если проверка совпала:

1. Приложение сначала устойчиво записывает маркер незавершённой очистки в `noBackupFilesDir` и синхронизирует его на диск.
2. На экране блокировки показывается сообщение **«Попытки исчерпаны»**.
3. Через короткую паузу открывается экран очистки. Подтверждение и отмена не предлагаются.
4. Удаляются ключи SecNote из Android Keystore, биометрическая привязка, соль и проверочный файл основного пароля, verifier секретного пароля, заметки, списки, зашифрованные файлы, кэш и настройки приложения.
5. После проверки очистки маркер удаляется и открывается первоначальная настройка SecNote.

Если Android завершит приложение или устройство перезагрузится после записи маркера, следующий запуск продолжит очистку **до** показа экрана входа или настройки. Если очистка не завершилась, старые данные не открываются; экран предлагает повторить операцию.

## Технические ограничения

Приложение удаляет собственные локальные данные и ключи. Перезапись файлов выполняется best-effort. Обычное Android-приложение не может гарантировать физическую перезапись всех старых блоков NAND/flash-памяти из-за wear levelling и поведения контроллера накопителя. Удаление ключей шифрования делает старое зашифрованное содержимое недоступным SecNote, но не гарантирует уничтожение экспортированных копий, облачных версий, сторонних резервных копий или оригиналов вне закрытого каталога приложения.

## Обновление 1.3.2 → 1.3.3

Устанавливайте новый APK **поверх** SecNote 1.3.2. Не удаляйте приложение перед обновлением. `applicationId` остаётся `infernics.notes`, а конфигурация подписи использует тот же файл `signing/secure-notes-debug.keystore`. Не заменяйте и не удаляйте этот keystore.

## Сборка

В репозитории находится `.github/workflows/build-apk.yml`. Workflow запускает `clean testDebugUnitTest assembleDebug`, включая unit-тесты проверки секретного verifier. После успешного выполнения GitHub Actions публикует `app-debug.apk` в Artifacts.

**Приватность:** репозиторий должен быть Private — в нём хранится ключ подписи APK.
