# SecNote 1.3 — защищённые заметки и файловое хранилище Android

Проект собирается онлайн через GitHub Actions. Устанавливать Android Studio или Android SDK на компьютер не требуется.

## Изменения версии 1.3

- В настройках появился переключатель **«Блокировка скриншотов»**. При включении Android-флаг `FLAG_SECURE` запрещает системные снимки экрана и захват защищённого окна при записи/трансляции экрана. Ограничение относится к окну приложения; поведение отдельных прошивок может отличаться.
- В файловом хранилище доступен режим множественного выбора. Войти в него можно кнопкой выбора в верхней панели или долгим нажатием на файл/фото. Выбранные элементы можно массово расшифровать в выбранную пользователем папку либо удалить из зашифрованного хранилища.
- Панель главного экрана показывает только иконку-шестерёнку стандартного размера 24 dp, без подписи «Настройки».
- Тип **«Список»** работает как встроенный чек-лист: каждая строка имеет собственный чекбокс и редактируется прямо в заметке. Нажатие Enter/Next создаёт следующую пустую строку с чекбоксом и переводит курсор в неё. Пункты не являются отдельным блоком под обычной заметкой.
- Сохранена совместимость с предыдущими записями, которые содержали чек-листы: старые пункты загружаются в новый формат списка.
- Галерея изображений и отдельный список документов в файловом хранилище сохранены.

## Основные параметры

- Название: **SecNote**.
- Package / Application ID: **`infernics.notes`**.
- Версия: **1.3**, versionCode **4**.
- Минимальная версия Android: **8.0 (API 26)**.
- Основной пароль; ключ выводится через PBKDF2-HMAC-SHA256 (250 000 итераций, случайная соль).
- Заметки и файлы шифруются AES-256-GCM. Для файлов используется потоковое шифрование с проверкой целостности.
- Дополнительный вход: сильная биометрия Android через `BiometricPrompt` и Android Keystore. Пароль остаётся резервным способом.
- Автоблокировка при уходе приложения в фон сохранена.
- Тёмная графитовая и светлая нейтральная темы.
- Отдельное файловое хранилище не меняет основной сценарий работы с заметками.
- Android Auto Backup отключён (`allowBackup=false`).

## Работа со списками

Нажмите `+` и выберите **«Список»**. Появится первая строка с чекбоксом. Введите пункт и нажмите Enter/Next на клавиатуре — приложение добавит следующую строку с чекбоксом и поставит на неё курсор. Галочка отмечает пункт выполненным; текст такого пункта отображается зачёркнутым. Строки можно добавлять также кнопкой «Новая строка» и удалять отдельно. Состояния чекбоксов сохраняются вместе со списком в зашифрованной записи.

Обычная **«Заметка»** остаётся обычным текстом и не получает чекбоксы.

## Массовые действия с файлами

В файловом хранилище нажмите иконку выбора в верхней панели или удерживайте нужный файл/изображение. После выделения появится счётчик и команды:

- **Расшифровать выбранные** — выбрать папку назначения системным диалогом Android; каждый выбранный файл экспортируется в неё в исходном виде.
- **Удалить выбранные** — удалить зашифрованные объекты SecNote после отдельного подтверждения.

Выбор поддерживает и фотографии в верхней галерее, и документы/прочие файлы в списке ниже. Отмена режима выбора — стрелкой «Назад».

## Блокировка скриншотов

По умолчанию настройка выключена. При включении приложение устанавливает `WindowManager.LayoutParams.FLAG_SECURE`; при выключении флаг снимается. Защита действует на окно SecNote. Она не может запретить внешнюю камеру, а поведение некоторых сторонних прошивок зависит от реализации Android-производителя.

## Формат хранения и совместимость

Каждая заметка хранится отдельным AES-256-GCM зашифрованным JSON-файлом в приватном каталоге приложения. JSON содержит тип (`NOTE` или `LIST`), текст, строки списка и состояния чекбоксов. При чтении старых записей без поля `kind` непустой массив `checklist` распознаётся как список.

Файлы находятся отдельно от заметок в приватном каталоге `file_vault`. Сами данные и метаданные зашифрованы. Миниатюры изображений создаются во временном приватном cache-файле; после декодирования этот временный файл удаляется.

При импорте в защищённое хранилище сначала создаётся и проверяется зашифрованная копия. Затем приложение пытается перезаписать исходный документ и удалить его, если это позволяет провайдер Android. **Физическое уничтожение исходных данных гарантировать нельзя**: Android Storage Access Framework, облачные провайдеры, файловая система и flash translation layer могут не предоставить прямой доступ к исходным блокам. Проверяйте сообщение приложения о результате и при необходимости удаляйте оригинал вручную.

При экспорте из хранилища файл записывается в выбранное пользователем место в расшифрованном виде. После экспорта эта копия уже не защищена SecNote.

## Биометрия

При включении биометрии Android Keystore оборачивает копию уже существующего ключа хранилища. Получение этой копии требует успешной сильной биометрической проверки через `BiometricPrompt.CryptoObject`. Основной пароль сохраняется как резервный путь входа. После изменения зарегистрированных биометрических данных ключ может быть инвалидирован системой; тогда войдите основным паролем и подключите биометрию заново.

## Сборка APK через GitHub Actions

Workflow: `.github/workflows/build-apk.yml`.

Он запускается при push в ветку `main` или вручную из вкладки **Actions**. На GitHub runner устанавливаются JDK 17, Android SDK 35 и Gradle 8.7. Затем выполняются `clean`, `testDebugUnitTest` и `assembleDebug`. При успехе отдельным artifact загружается файл `app-debug.apk`.

## Полная инструкция обновления репозитория

См. файл `GITHUB_GUIDE_RU.txt` в корне архива. Он описывает как обновление существующего репозитория, так и первоначальную загрузку в новый репозиторий, включая ручное создание скрытого файла workflow через веб-интерфейс GitHub.

## Подпись и безопасность репозитория

- Рекомендуется держать репозиторий **Private**: внутри находится debug-keystore, используемый для подписи тестовых APK.
- Для обновления установленной версии не удаляйте и не заменяйте `signing/secure-notes-debug.keystore` другим ключом. В этом архиве сохранён тот же ключ, который был в архиве SecNote 1.2.
- Если файл keystore уже находился в публичном репозитории, считайте ключ раскрытым для целей подписи. Это не раскрывает локальный ключ шифрования заметок, но такой keystore не следует использовать для публичного релиза или Google Play.
- Debug APK предназначен для личной установки и тестирования, не для публикации в Google Play.
- Потеря основного пароля может привести к безвозвратной потере доступа к данным.
